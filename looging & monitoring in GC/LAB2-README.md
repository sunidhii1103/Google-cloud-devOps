# Google Cloud Lab: Alerting in Google Cloud

## Overview

This lab demonstrates how to deploy a Python Flask application to Google App Engine and implement monitoring and alerting using Google Cloud Observability.

The lab focuses on monitoring application latency, creating alerting policies, configuring notification channels, investigating logs, and responding to incidents generated by performance degradation.

---

## Objectives

* Download and test a sample Flask application.
* Deploy an application to Google App Engine.
* Examine App Engine logs.
* Monitor application latency using Metrics Explorer.
* Configure notification channels.
* Create latency-based alerting policies.
* Generate application performance issues.
* Trigger and investigate monitoring incidents.
* Analyze alert behavior and incident management.

## Tasks Performed

### 1. Downloaded and Tested Sample Application

Cloned Google's sample training repository:

```bash
git clone --depth 1 https://github.com/GoogleCloudPlatform/training-data-analyst.git
```

Navigated to the application directory:

```bash
cd ~/training-data-analyst/courses/design-process/deploying-apps-to-gcp
```

Installed dependencies:

```bash
pip3 install -r requirements.txt
```

Executed the Flask application locally:

```bash
python3 main.py
```

Verified application functionality using Cloud Shell Web Preview.

---

### 2. Deployed Application to App Engine

Created the App Engine configuration file:

```yaml
runtime: python312
```

Created the App Engine application:

```bash
gcloud app create --region=us-east1
```

Deployed the application:

```bash
gcloud app deploy --version=one --quiet
```

Verified successful deployment through the App Engine Dashboard.

---

Used App Engine logging tools to inspect application requests and activity.

### 5. Created Notification Channel

Configured an email notification channel for alert delivery.

Notification Type:

```text
Email
```

Purpose:

* Receive alerts when latency thresholds are exceeded
* Enable rapid incident response

---

### 6. Created Alerting Policy

Configured a latency-based alert.

Alert Configuration:

| Setting            | Value                                     |
| ------------------ | ----------------------------------------- |
| Metric             | GAE Application → HTTP → Response Latency |
| Rolling Window     | 1 Minute                                  |
| Threshold Position | Above Threshold                           |
| Threshold Value    | 8000 ms                                   |
| Condition Name     | Response latency [MEAN] for 99th% over 8s |
| Policy Name        | Hello too slow                            |

Purpose:

* Detect abnormal application response times
* Generate incidents automatically
* Notify administrators

---

### 7. Simulated Application Performance Issues

Modified the Flask application to intentionally introduce latency.

Added imports:

```python
import time
import random
import json
```

Updated route:

```python
@app.route("/")
def main():
    model = {"title": "Hello GCP."}
    time.sleep(10)
    return render_template('index.html', model=model)
```

This introduced a 10-second delay for every request.

---

### 8. Redeployed Updated Application

Deployed the modified version:

```bash
gcloud app deploy --version=two --quiet
```

Verified the application was serving delayed responses.

### 9. Generated Traffic

Used a continuous request loop to create application traffic:

```bash
while true; do
curl -s https://$DEVSHELL_PROJECT_ID.appspot.com/ | grep -e "<title>" -e "error"
sleep .$[( $RANDOM % 10 )]s
done
```

Purpose:

* Generate monitoring data
* Trigger latency alerts
* Simulate real-world application usage
