# Log Analytics on Google Cloud

## Overview

This lab explored **Google Cloud Logging** and **Log Analytics** for monitoring, troubleshooting, and analyzing applications running on **Google Kubernetes Engine (GKE)**. Cloud Logging provides a centralized platform to collect, store, search, analyze, and monitor logs generated by cloud resources and applications.

Using a microservices-based e-commerce application deployed on GKE, I learned how to investigate logs, create log buckets, enable Log Analytics, configure log routing, and analyze Cloud Audit Logs.

---

## Objectives

* Explore application logs using Cloud Logging.
* Analyze logs generated by Kubernetes workloads.
* Build and execute queries using Logging Query Language (LQL).
* Enable and use Log Analytics.
* Create and manage log buckets.
* Route logs using log sinks.
* Investigate Cloud Audit Logs and Data Access Logs.
* Gain operational visibility into a distributed microservices environment.

## Lab Tasks Completed

### 1. Explored Cloud Logging

* Accessed Logs Explorer.
* Examined logs generated by Kubernetes workloads.
* Investigated resource types, severity levels, and log metadata.
* Filtered logs to isolate application-specific events.

### 2. Queried Application Logs

* Built custom queries using Logging Query Language (LQL).
* Filtered logs by resource type, severity, and log names.
* Analyzed application behavior and troubleshooting information.

Example query:

```sql
resource.type="k8s_container"
```

### 3. Enabled Log Analytics

* Upgraded the default log bucket to support Log Analytics.
* Opened log data using the Log Analytics interface.
* Explored SQL-based analytics capabilities for log analysis.

### 4. Created a New Log Bucket

* Created a log bucket named `day2ops-log`.
* Enabled Log Analytics.
* Linked the bucket to a BigQuery dataset named `day2ops_log`.

### 5. Created a Log Sink

* Created a sink named `day2ops-sink`.
* Routed Kubernetes container logs into the custom log bucket.
* Applied filtering to capture relevant application logs.

### 6. Investigated Cloud Audit Logs

* Viewed Activity Audit Logs.
* Analyzed Cloud Storage operations.
* Identified users performing actions using:

```text
protoPayload.authenticationInfo.principalEmail
```

* Examined fields such as:

  * serviceName
  * methodName
  * resourceName
  * timestamp

### 7. Explored Data Access Logs

* Filtered and analyzed Data Access audit logs.
* Observed data read and write operations.
* Investigated access patterns across cloud resources.

## Key Concepts Learned

### Cloud Logging

A fully managed logging service that enables:

* Log collection
* Search and filtering
* Monitoring
* Troubleshooting
* Alerting

### Log Analytics

Provides advanced log analysis capabilities through:

* SQL-based queries
* BigQuery integration
* Large-scale log analytics

### Log Buckets

Storage containers for logs with configurable:

* Retention periods
* Access controls
* Analytics support

### Log Sinks

Used to route logs to:

* Log Buckets
* BigQuery
* Cloud Storage
* Pub/Sub

### Cloud Audit Logs

Provide visibility into:

> "Who did what, where, and when?"

Audit log categories include:

* Admin Activity
* Data Access
* System Event
* Policy Denied

### Logging Query Language (LQL)

Used to filter and analyze logs efficiently within Logs Explorer.
